# نظام إدارة العيادة الطبية

نظام عربي لإدارة عيادة د. رغد حسين، مبني بـ React وExpress وTypeScript وPostgreSQL.

يشمل تسجيل الدخول والصلاحيات، المرضى والمواعيد ومنع التعارض، الملف الطبي والقياسات وBMI، الحساسيات والأمراض المزمنة، الزيارات والتشخيصات، الوصفات والتحاليل والنتائج والأشعة والمتابعات، المرفقات الطبية الخاصة، قائمة الانتظار، التقارير، الإعدادات وسجل النشاط.

الواجهة عربية RTL ومتجاوبة مع متصفحات الهاتف والتابلت واللابتوب، وتوفر شريط تنقل سفلياً وأزرار لمس ونوافذ مناسبة للشاشات الصغيرة.

يتضمن أيضاً تقويماً يومياً وأسبوعياً وشهرياً مع إعادة جدولة بالسحب، مركز إشعارات، بحثاً عاماً، إدارة الأطباء وساعات عملهم، إدارة المستخدمين والأدوار والصلاحيات، وإدارة أسباب الزيارة. إعدادات SMS وWhatsApp تحفظ تجهيزات الربط فقط ولا ترسل رسائل دون API حقيقي.

## المتطلبات

- Node.js 18 أو أحدث
- npm 7 أو أحدث

## التشغيل

```bash
npm install
npm run dev
```

تعمل الواجهة افتراضيًا على `http://localhost:3000` والخادم على `http://localhost:5000`.

## التحقق والإنتاج

```bash
npm run typecheck
npm test
npm run build
npm start
```

عند أول تشغيل تظهر شاشة إعداد آمنة لإنشاء حساب د. رغد. لا توجد كلمة مرور افتراضية داخل الكود.

## قاعدة البيانات والإعداد

- في Replit أضف PostgreSQL Database؛ سيستخدم التطبيق `DATABASE_URL` تلقائيًا.
- أضف `NODE_ENV=production` و`CLIENT_ORIGIN=https://عنوان-التطبيق` إلى Replit Secrets عند النشر.
- في Render استخدم خدمة Web Service وليس Static Site. ملف `render.yaml` يضبط البناء والتشغيل والفحص الصحي تلقائياً، ويطلب منك إدخال `DATABASE_URL` كقيمة سرية لا تُحفظ داخل GitHub.
- يتعرّف التطبيق تلقائياً على رابط Render من `RENDER_EXTERNAL_URL`. عند إضافة نطاق مخصص منفصل يمكنك أيضاً وضعه في `CLIENT_ORIGIN`.
- ملف `.replit` يجهز أوامر التطوير والبناء والتشغيل، والخادم يقدم الواجهة المبنية في وضع الإنتاج.
- محليًا يستخدم التطبيق PostgreSQL مضمّنًا داخل `backend/data/clinic-db` للتطوير فقط.
- تُنفذ ترحيلات قاعدة البيانات تلقائيًا وبترتيب آمن عند بدء الخادم.
- إذا وجد ملف مرضى من النسخة السابقة، تُرحل سجلاته مرة واحدة مع الحفاظ على الملف الأصلي.
- انسخ `.env.example` إلى `.env` لتعديل إعدادات التشغيل محليًا.
- مرفقات PDF وJPG وPNG (حتى 8 ميغابايت) تُحفظ داخل PostgreSQL وتُنزّل عبر مسار محمي فقط؛ لا توجد روابط ملفات عامة.

## النشر على Render

1. ارفع المشروع كاملاً إلى GitHub مع الملف `render.yaml` في جذر المستودع.
2. في Render اختر **New +** ثم **Blueprint** واربط المستودع.
3. عندما يطلب Render قيمة `DATABASE_URL`، الصق رابط اتصال PostgreSQL من Neon. لا تضع الرابط في أي ملف ولا ترسله إلى GitHub.
4. أكمل إنشاء الـBlueprint؛ سيبني Render المشروع ويشغله بواسطة `npm start`.

إذا كنت تستخدم Web Service أُنشئت سابقاً، أضف `DATABASE_URL` من صفحة **Environment** ثم اختر **Save Changes** وأعد نشر آخر نسخة.

## الاختبار على GitHub

يحتوي المشروع على GitHub Actions داخل `.github/workflows/ci.yml`. عند كل رفع إلى فرع `main` أو فتح Pull Request، ينفذ GitHub تلقائياً:

- تثبيت الحزم من `package-lock.json`.
- فحص TypeScript للواجهة والخادم والمكتبة المشتركة.
- اختبارات قاعدة البيانات والمستخدمين والتحقق من بيانات المرضى.
- بناء نسخة الإنتاج كاملة.
- تشغيل الخادم مؤقتاً وفحص `/api/health`.
- حفظ ناتج البناء باسم `medical-clinic-production-build` في صفحة Actions.

بنية قاعدة البيانات وترحيلاتها وبياناتها المرجعية موجودة في المستودع. قاعدة المرضى الفعلية وكلمة مرور PostgreSQL لا تُرفع إلى GitHub؛ تُربط قاعدة الإنتاج من خلال `DATABASE_URL` داخل Render أو منصة الاستضافة.

## تنبيه أمني

يدعم النظام جلسات آمنة وصلاحيات وسجل نشاط. عند النشر استخدم Replit Secrets وPostgreSQL المُدار، وفعّل HTTPS والنسخ الاحتياطية وسياسة احتفاظ بالبيانات المتوافقة مع المتطلبات القانونية المحلية.
